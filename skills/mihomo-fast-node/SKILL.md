# 下载通道选优（直连与代理同台实测）

下载被限速时，不要干等，也不要默认「代理一定更快」。

**核心原则：只看这台机器下载这个文件的真实结果——既看「能不能拿到」，也看「多快」；直连和代理都是候选。**

---

## 什么时候用 / 不用

| 用 | 不用 |
|---|---|
| 单个大文件（> 50 MB）下得慢或反复中断 | 页面打不开、API 调不通（不是下载问题） |
| 不确定该走直连还是代理 | 需要长期监控节点质量（这脚本只看当下） |
| 怀疑某节点被目标站封了（403/429/验证页） | 目标需要登录态且脚本拿不到 cookie |

## 一键使用

```bash
bash "${CLAUDE_SKILL_DIR:-.}/scripts/pick-fastest.sh" "<目标URL>"
```

它会依次完成：探活 → 找可切换的入口组 → 逐个切组实测 → 剔除不可用 → 排名 → 切冠军 → 后台起下载。

**输出三段**：人看的排行榜（含状态列）+ 下载命令 + 末行 `RESULT_JSON`（机器可读）。

```bash
# 下面统一用 $PICK 代表脚本路径，避免裸路径（插件打包会丢执行位）
PICK="$(dirname "$0")/scripts/pick-fastest.sh"   # 实际使用时指向本 skill 的 scripts 目录

# 只测不下（安全预演）
DRY_RUN=1 bash "$PICK" "<URL>"

# 指定入口组，跳过自动探测
GROUP=Proxy bash "$PICK" "<URL>"

# 恢复上次切走之前的节点
bash "$PICK" --restore
```

## 它怎么判定（这是与普通测速脚本的关键差别）

每轮只发 **一次** 请求，同时拿到「可用性」和「速度」：

| 拿到的东西 | 判定 | 处理 |
|---|---|---|
| 200 / 206 + 二进制类型 | `PASS` | 进入排名 |
| 403 | `BLOCKED_403` | 剔除：出口 IP 被站点拒绝 |
| 401 | `AUTH_401` | 剔除：需要 token / 登录 |
| 429 | `RATE_429` | 剔除：该出口被限流 |
| 200 但内容是 `Just a moment...` 等 | `CHALLENGE` | 剔除：Cloudflare 人机验证 |
| 200 但返回 HTML / 不足 512 字节 | `SUSPECT_HTML` | 剔除：拿到的是网页不是文件 |
| 连不上 / 超时 | `NET_ERROR` | 剔除 |

**为什么必须先判可用性**：被封的站点常返回 1 KB 错误页，而 `curl` 算出的瞬时速度可能极高——只看速度会让「根本下不了东西」的节点夺冠。

**封锁是「按目标 URL」判定的**：同一节点可能下不了 Cloudflare，但下 HuggingFace 完全正常。脚本不缓存黑名单。

## 参数

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `MIHOMO_API` | `http://127.0.0.1:9092` | 控制接口（external-controller） |
| `MIHOMO_PROXY` | `http://127.0.0.1:7890` | 代理端口（mixed-port） |
| `GROUP` | 自动探测 | 可切换的入口组，如 `Proxy` / `节点选择` |
| `SAMPLE_MB` | `1` | 第一轮每组采样大小 |
| `PRECISE_MB` | `8` | 前 2 名精测采样 |
| `TIMEOUT` | `6` | 单次请求超时（秒） |
| `EARLY_EXIT_RATIO` | `3` | 冠军领先该倍数即跳过精测 |
| `MAX_TRAFFIC_MB` | `30` | 总流量硬上限，超了立刻停 |
| `SKIP_DIRECT` | `0` | `1` = 不测直连（TUN 下自动置 1） |
| `TARGET_DIR` | 当前目录 | 下载落盘目录 |
| `START_DOWNLOAD` | `1` | `0` = 只给建议不起下载 |
| `CONCURRENCY` | `16` | aria2c 连接数 `-x/-s` |
| `DRY_RUN` | `0` | `1` = 不启动下载 |
| `ASSUME_NO_PROMPT` | `0` | `1` = 非交互，缺参数直接报错不提问 |

## 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 全部 `BLOCKED_403`，只有直连可用 | 站点封了这批机房 IP | 走直连，或换镜像站 |
| 全部 `CHALLENGE` | Cloudflare 人机验证 | 换节点、加 UA/Referer；脚本不会去破验证 |
| 个别节点 `RATE_429` | 该出口被限流 | 换节点，或把 `CONCURRENCY` 降到 4 |
| 直连 403、代理 200 | 目标站封了你家宽 IP | 走代理（这就是「直连也是候选」的意义） |
| 所有通道 < 1 MB/s | 本地出口或运营商限速 | 换网络，或多连接并发 |
| 切换被 API 拒绝（`SWITCH_FAIL`） | 该成员不属于入口组 | 脚本自动剔除，说明 `GROUP` 选错时可手动指定 |
| 测出 0 且 `NET_ERROR` | TUN 全局代理 / 网络中断 | 脚本已自动跳过直连；仍失败则检查代理端口 |
| 下载完哈希不符 | 多连接中断后续传留空洞 | 删掉重下，别混用 aria2c 和 curl 续传 |

## 副作用与恢复

| 行为 | 说明 |
|---|---|
| 切组是全局的 | 会影响所有走代理的服务；脚本记下原节点，可用 `--restore` 还原 |
| 暂停下载进程 | **只暂停命令行里含目标 URL 的** `aria2c`/`curl`/`wget`，用 `SIGSTOP`（暂停）不是 `kill`，结束自动 `SIGCONT` |
| 下载启动后不恢复节点 | 否则会把正在跑的下载掐断；原节点记在 `~/.local/state/mihomo-fast-node/state.env` |
| 流量 | 一轮约 `候选数 × 1 MB`，精测再 `2 × 8 MB`，硬上限 `MAX_TRAFFIC_MB` |

## 已知局限

- **不能真并发**：标准 mihomo 只有一个 `mixed-port` 出口，切组是全局单例，所以候选只能串行测。配置了多个 `listeners` 才能并行，脚本目前不利用这一点。
- **测的是瞬时吞吐**，不代表节点稳定性；单次采样存在抖动，故对前 2 名做二次精测。
- **不破验证码**：Cloudflare 挑战页判为不可用后直接跳过，不做绕过尝试。
- **范围仅限单个 URL**：换个站点结论可能完全不同，不要跨站点复用。
